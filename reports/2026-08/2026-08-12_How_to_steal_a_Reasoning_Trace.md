### Speculative Decoding, 어떤 이름으로 불리든 디스틸레이션은 달콤할 것입니다
Aug 12, 2026Share논문이 하루아침에 헤드라인을 장식하는 일은 흔치 않습니다. 국내외를 막론하고 이해할 만한 이유로 정렬(alignment), 보안(security), CoT(chain of thought) 모니터링의 Interpretability 벤 다이어그램에 대한 관심이 다시 높아지고 있으며, 따라서 오늘 소개할 논문은 더할 나위 없이 시기적절하게 등장했습니다:

![X avatar for @kotekjedi_ml](https://pbs.substack.com/profile_images/1869805907472740352/KDWcthSp.jpg)
o1 출시 이후, 프론티어 랩 추론 모델들은 디스틸레이션에 대한 우려로 암호화 서명을 통해 자신들의 트레이스를 숨겨왔습니다 (물론 이것이 중국 랩들이 그들을 비난하는 것을 막지는 못했지만요). 첫 번째 침해 사례는 5월 Matthew Green이 책임감 있게 보고했으며, 그는 작동 방식을 분석하고 레이턴시 측정을 사용하여 이러한 트레이스를 간접적으로 리플레이하고 사이드 채널 공격하는 방법을 알아냈습니다. 오늘 소개할 논문은 이러한 암호화된 사고를 디코딩하여 다른 모델/세션/사용자에게 포팅하는 것이 가능하며, 그 결과 오픈 모델을 극적으로 개선할 수 있음을 보여줍니다.

![Image](https://substack-post-media.s3.amazonaws.com/public/images/18b4c6ea-cef8-43ba-9ef6-4aa7ae493944_3300x1890.jpeg)
다음은 경고 메시지입니다:
> "더 나아가, 만약 여러분이 암호화된 추론 블롭이 포함된 Claude Code/Codex 세션을 온라인에 공유했다면, 이는 디코딩되어 개인 데이터를 유출할 수 있습니다. 저희는 약 7,000개의 공개 트레이스를 예비 스캔하여 62개의 고유한 API key, 33개의 이메일 주소, 33개의 비밀번호 및 기타 민감한 데이터를 발견했습니다." (64개는 추론 블록 내부에만 나타났으며 가시적인 세션에는 없었습니다.)
저자들은 또한 다음과 같은 정렬 문제를 자세히 설명합니다:
- CoT 요약기가 답변을 숨기는 문제
- 이해할 수 없는 추론
- 부정행위 고려 사항
- 웹사이트 공격
웹사이트에 더 많은 예시가 있습니다.

![](https://substack-post-media.s3.amazonaws.com/public/images/5fea1dc2-4c18-4636-8bbd-2011993d78e3_1611x1041.png)
해당 기술은 논문에서 다음과 같이 설명됩니다:
1. API 응답에서 합법적인 암호화/서명된 추론 블록을 얻습니다.
2. 해당 블록을 동일한 제공업체의 약한 모델에 대한 다른 요청(잠재적으로 다른 계정/세션)으로 리플레이합니다.
3. 이를 어시스턴트/모델 턴에 배치하고 약한 모델에 프롬프트하거나 프리필하여 첨부된 추론을 전사하도록 합니다.
4. 반복적으로 샘플링하고, 거부된 응답을 버리며, 선택적으로 여러 노이즈가 있는 전사본을 조정합니다.
논문은 모델별로 약간의 변형이 있는 구체적인 템플릿을 제공합니다:
- Claude: 서명된 사고 블록을 Haiku 4.5에 리플레이한 다음, <thinking-copy>와 같은 어시스턴트 프리필을 추가합니다.
- GPT: encrypted_content 추론 항목을 조작된 대화에 여러 번 주입하고, 최대 50개의 출력을 샘플링합니다. 또한 청크된 연속을 사용하여 약 50 토큰의 문자 그대로의 출력 임계값을 우회하는 방법을 설명합니다.
- Gemini: thought_signature를 <thought> 프리필이 있는 모델 턴에 첨부한 다음, 반복 샘플링 및 조정을 사용합니다.

- 프론티어 API 취약점으로 숨겨진 추론 노출: @kotekjedi_ml의 널리 논의된 공개에 따르면, 프론티어 API 전반의 취약점으로 인해 "암호화된" 숨겨진 추론을 추출할 수 있었으며, 대부분의 쿼리된 프롬프트에서 복구된 토큰 수가 청구된 사고 토큰과 1:1로 일치했다고 주장합니다. 후속 조치로, 팀은 약 7,000개의 공개 트레이스 스캔에서 디코딩된 블롭에서 62개의 고유한 API key, 33개의 이메일 주소, 33개의 비밀번호 및 기타 민감한 데이터를 발견했다고 보고했습니다 @kotekjedi_ml. @jonasgeiping의 추가적인 맥락은 트레이스를 공개적으로 공유하는 즉각적인 프라이버시 위험과 운영 보안(operational-security) 함의를 모두 강조합니다. 조사 중에 그들은 광범위한 사이버 사고 중에 유출된 Hugging Face 프로덕션 key를 발견했다고 보고했습니다. 여러 게시물은 또한 디코딩된 CoT가 간결하고, 파편화되어 있으며, 다국어이거나, 사실상 "뉴럴리즈(neuralese)"일 때 모니터링이 얼마나 어려워지는지 강조합니다 @jonasgeiping, @scaling01, @eliebakouch. 실용적인 결과는 다음과 같습니다: 랩들이 추론을 숨기더라도 툴 인터페이스가 이를 다시 노출할 수 있습니다. @_can1357은 deep_think 툴을 제공하면서 명시적인 사고를 비활성화하더라도 내부 형식의 CoT 출력을 유도할 수 있다고 언급합니다.
- 기술적으로 이것이 의미하는 바: 논의는 "심각한 프라이버시/안전 문제"와 "확장 가능한 디스틸레이션 경로가 아님"으로 나뉘었습니다. @vipulved는 이 공격이 모델 학습을 위한 CoT의 실질적인 대량 절도를 의미하지는 않으며, 암호화를 강력한 기밀성 장벽이라기보다는 상태 비저장 분산 인퍼런스 프로토콜 최적화로 간주한다고 주장합니다. 그럼에도 불구하고, 이번 사건은 몇 가지 점을 명확히 합니다: 공개 트레이스 공유는 위험합니다; 숨겨진 CoT는 신뢰할 수 있는 모니터링 인터페이스가 아닙니다; 그리고 랩들은 샌드박싱, 텔레메트리, 툴 표면에 대한 더 강력한 보장을 필요로 할 수 있습니다 @BlackHC. 이와 병행하여, 별도의 스레드에서는 EU 스타일의 규제 압력 하에 AI 텍스트 워터마킹에 대해 논의했습니다. @trq212는 랩들이 워터마킹과 텍스트 감지 API를 추가하고 있다고 말했습니다. 비평가들은 이것이 출력을 부풀리거나 코드/문서의 간결성을 해칠 수 있는지 의문을 제기했습니다 @wightmanr. 다른 이들은 엔트로피 예산이 충분히 커서 서명이 미묘할 수 있으며, 특히 긴 출력의 경우 더욱 그렇다고 주장했습니다 @RyanGreenblatt, @giffmana.
